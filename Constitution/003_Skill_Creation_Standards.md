# Purpose

This document defines the permanent standard for creating, updating, reviewing, and maintaining reusable filmmaking skills.

Every skill stored in the repository must comply with these standards.

These standards ensure consistency, quality, maintainability, and long-term usability.

---

# Definition of a Skill

A skill is the smallest reusable unit of filmmaking knowledge.

A skill captures a single reusable cinematic principle that can be applied across multiple productions.

A skill is not:

- an observation
- a movie scene
- an actor's habit
- a character profile
- a screenplay
- a tutorial
- a prompt

A skill explains **how**, **why**, and **when** a filmmaking technique should be applied.

---

# Skill Objectives

Every skill should:

- solve one filmmaking problem
- explain one reusable principle
- improve future AI reasoning
- improve future human creativity
- connect with related knowledge

A skill should never attempt to teach an entire discipline.

One skill.

One principle.

---

# Skill Quality Principles

Every skill must be:

- reusable
- timeless
- psychologically explainable
- actor-independent
- movie-independent
- implementation-independent
- clearly written
- technically accurate

If any principle cannot be satisfied, the skill should not be accepted.

---

# Skill Metadata

Every skill must contain structured metadata.

Required metadata includes:

- Skill ID
- Title
- Category
- Version
- Status
- Created Date
- Last Updated
- Tags
- Confidence Score

Optional metadata:

- Related Skills
- Aliases
- Notes
- References

Metadata must remain machine-readable.

---

# Required Skill Sections

Every skill must contain the following sections.

## Definition

A concise explanation of the reusable principle.

---

## Purpose

Why the skill exists.

What filmmaking problem it solves.

---

## Psychology

Explain the psychological mechanism behind the skill.

Answer:

Why does this work?

---

## Story Function

Describe how the skill contributes to storytelling.

---

## Character Function

Describe what it communicates about the character.

---

## Internal State

Describe the character's internal emotional condition.

---

## External Behaviour

Describe visible behaviour.

Avoid actor-specific wording.

---

## Dialogue Guidance

Explain how dialogue should interact with the skill.

If dialogue is not relevant, explicitly state so.

---

## Voice Guidance

Explain vocal behaviour where applicable.

If voice is not relevant, explicitly state so.

---

## Body Language

Describe important physical behaviour.

---

## Timing

Explain when the behaviour should begin, peak, and conclude.

---

## Rhythm

Describe pacing.

Fast.

Slow.

Gradual.

Abrupt.

---

## Camera Considerations

Explain camera techniques that best support the skill.

Do not prescribe one specific implementation.

---

## Lighting Considerations

Describe lighting characteristics that reinforce the skill.

---

## Music & Sound Considerations

Explain how audio may enhance the intended emotional effect.

---

## Best Used When

Describe situations where the skill is most effective.

---

## Avoid When

Describe situations where the skill should not be used.

Understanding limitations is as important as understanding strengths.

---

## Common Mistakes

List common implementation mistakes.

Explain why they reduce effectiveness.

---

## Related Skills

Reference related skills using Skill IDs.

Never duplicate explanations.

---

## Repository Decision

Every skill must document why it was introduced into the repository.

Possible reasons include:

- Existing knowledge was insufficient.
- Existing knowledge was expanded.
- A meaningful variation was identified.
- A broad skill was split into focused skills.
- Multiple overlapping skills were merged.
- A genuinely new reusable principle was discovered.

The repository decision should explain **why this skill exists instead of another repository action**.

This section records the reasoning behind repository evolution and helps future contributors understand architectural decisions.

---

# Skill Relationships

Skills should form a connected knowledge graph.

Whenever appropriate, identify relationships such as:

- prerequisite
- complementary
- opposite
- refinement
- variation

Relationships should strengthen reasoning rather than increase complexity.

---

# Skill Granularity

Each skill should represent exactly one reusable principle.

If a document contains multiple independent principles:

Split it.

If two documents describe the same principle:

Merge them.

---

# Skill Evolution

Existing skills should evolve through refinement.

Creating a new skill should be the last option.

Preferred order:

1. Reuse existing skill
2. Improve existing skill
3. Create variation
4. Split
5. Merge
6. Create new skill

Repository growth should occur through improved understanding rather than increased file count.

---

# Skill Validation

Before a skill is accepted, verify:

## Repository Justification

Is creating this skill the best repository decision compared to updating, merging, splitting, or reusing existing knowledge?

## Reusability

Can this be applied to many productions?

## Independence

Is it independent of actors, movies, and technology?

## Explainability

Does it explain why it works?

## Practicality

Can another filmmaker apply it?

## Consistency

Does it follow repository standards?

## Uniqueness

Does an equivalent skill already exist?

If any answer is No, revise or reject the skill.

↓

↓

↓

---

# Success Criteria

A successful skill should:

- teach one principle exceptionally well
- improve repository quality
- reduce ambiguity
- strengthen related knowledge
- improve future reasoning

Quality is measured by usefulness, not length.

---

# Final Principle

Every skill accepted into this repository should make future filmmaking decisions more intelligent, more consistent, and more explainable.

If a skill does not meaningfully improve the repository, it should not be added.
