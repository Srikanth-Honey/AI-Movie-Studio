# Purpose

This document defines the review process for all knowledge entering the AI Movie Skills Repository.

Its purpose is to ensure that repository quality continuously improves while preventing unnecessary growth, duplication, inconsistency, and architectural drift.

Every proposed contribution must pass through this review process before becoming part of the permanent knowledge base.

---

# Review Philosophy

Knowledge is earned.

It is never accepted simply because it is new.

The purpose of review is not to approve contributions.

The purpose is to determine the best possible outcome for the repository.

Sometimes that outcome is creating new knowledge.

Often it is improving knowledge that already exists.

---

# Repository First

Every review decision must prioritize the repository over the individual contribution.

Ask:

> "What makes the repository better?"

Never ask:

> "How can this observation become a new skill?"

---

# Review Workflow

Every proposed contribution follows this workflow.

```
Candidate Knowledge
        ↓
Understand
        ↓
Search Existing Knowledge
        ↓
Compare
        ↓
Decision
        ↓
Human Review
        ↓
Repository
```

Knowledge must never bypass review.

---

# Review Process

Every review consists of the following stages.

---

## Stage 1 — Understand

Understand the complete context before making any decision.

Identify:

- cinematic purpose
- storytelling purpose
- psychological intent
- filmmaking principle
- reusable value

Never classify knowledge before understanding it.

---

## Stage 2 — Repository Search

Search the repository before proposing changes.

Search should include:

- title
- tags
- related skills
- semantic similarity
- psychological concepts
- filmmaking concepts

Assume relevant knowledge already exists until proven otherwise.

---

## Stage 3 — Comparison

Compare the candidate against existing skills.

Determine whether the candidate:

- already exists
- extends existing knowledge
- overlaps existing knowledge
- contradicts existing knowledge
- introduces a genuinely new principle

Similarity alone does not imply duplication.

Reasoning must be considered.

---

# Allowed Review Outcomes

Every review must result in exactly one primary outcome.

---

## Outcome 1 — Reuse

Existing knowledge already satisfies the requirement.

No repository changes are required.

---

## Outcome 2 — Improve

The repository contains the principle.

The existing skill should be improved.

No new skill is created.

---

## Outcome 3 — Create Variant

The principle already exists.

The candidate represents a meaningful variation.

Create a linked variation.

---

## Outcome 4 — Merge

Multiple skills describe the same principle.

Merge them into one stronger skill.

Preserve history.

Do not lose information.

---

## Outcome 5 — Split

A skill contains multiple independent principles.

Split into focused reusable skills.

Retain relationships.

---

## Outcome 6 — Deprecate

Knowledge has been replaced by better understanding.

Mark the previous version as deprecated.

Never reuse IDs.

Maintain traceability.

---

## Outcome 7 — Create New

Only when:

- the principle is genuinely new
- repository coverage is improved
- duplication cannot be avoided

Creating new knowledge should be the least frequent review outcome.

---

## Outcome 8 — Reject

Reject knowledge when it is:

- actor-specific
- movie-specific
- implementation-specific
- duplicated
- speculative
- poorly understood
- not reusable
- lacking psychological explanation

Rejected knowledge should never enter the repository.

---

# Review Checklist

Every reviewer should answer the following questions.

## Understanding

Do I understand why this works?

---

## Reusability

Can this be applied to many productions?

---

## Timelessness

Will this remain valuable over time?

---

## Independence

Is it independent of:

- actors
- movies
- technologies
- AI models

---

## Explainability

Can the principle be explained clearly?

---

## Practical Value

Will another filmmaker benefit from this knowledge?

---

## Repository Impact

Does accepting this improve the repository?

---

## Duplication

Does equivalent knowledge already exist?

---

# Decision Priority

When multiple valid actions exist, choose the first applicable option.

1. Reuse
2. Improve
3. Variant
4. Merge
5. Split
6. Deprecate
7. Create New

Reject whenever repository quality would decrease.

Repository growth is never the primary objective.

Repository quality is.

---

# Human Review

AI systems recommend.

Humans decide.

Human reviewers should evaluate:

- reasoning
- repository impact
- clarity
- consistency
- relationships

Human approval is required before permanent acceptance.

---

# Continuous Improvement

Review standards themselves should evolve.

Whenever a review process consistently produces ambiguity or poor outcomes:

- identify the cause
- improve the standard
- preserve consistency

The review process is part of the repository's knowledge.

It should improve alongside the repository.

---

# Final Principle

Every review should leave the repository stronger than it was before.

The objective is not to maximize the number of accepted skills.

The objective is to maximize the long-term quality, consistency, and usefulness of the knowledge base.
